# Minimal Home v1.4.0

This release improves launcher reliability and maintainability, adds enforced
coding standards and runtime coverage, and refreshes the screenshots from a TV
running the release build.

## Fixes and behavior

- Live tiles and statistics continue updating when webOS incorrectly marks a
  focused foreground webview as hidden. This was reproduced and fixed on-device.
- Settings saves are serialized, and late responses cannot overwrite newer edits.
- The LG Home tile survives live refreshes. Failed Home launches clear their bypass.
- Home redirect cooldowns schedule retries; interrupted Luna subscriptions reconnect.
- Holding OK to open a tile menu cannot accidentally activate its first option.
- Live tile labels retain their full-width centered layout, and accent choices
  render as separate color dots; both were checked in TV screenshots.
- Back closes search; Backspace edits its query. Alphabetical sorting respects its
  selected order independently of pins.
- Input launches preserve allowed live per-port parameters without replacing the
  target app ID. Malformed or duplicate launch points are filtered.
- State writes are atomic. Request lifetimes, retries, logs, and stored preferences
  are bounded; identical icons are not repeatedly written to TV storage.

## Development

- Frontend sources now live in `launcher-app/src/`; the Python generator assembles
  the self-contained page. Preferences, validation, sorting, storage, and stream
  parsing use shared modules.
- ESLint and Prettier enforce the project conventions. Host-only npm dependencies
  are locked and excluded from deployment packages.
- JavaScript coverage reaches 100% of lines, statements, and functions, with
  91.44% branch coverage on the local validation run. Per-file CI gates require
  100% lines/statements/functions and at least 85% branches; runtime files are not
  excluded. Coverage measures executable JavaScript, not hardware compatibility.
- Node 22 test-runner compatibility and Windows installer-test PATH handling are
  fixed. Contributor, architecture, testing, and agent guides reflect the new layout.

## Device validation

Tested on an LG **43UR7500PSC**, firmware **33.31.61**, **webOS 10.3.1**,
with TV Node **16.20.2** and the Chrome **120** webview:

- Cold launch and live app/input discovery, including returning from another app.
- D-pad/OK/Back handlers, long-OK menu behavior, search, pin/hide/restore, rapid
  preference changes, and persistence after a webview restart.
- YouTube launch and switching to HDMI 2 through the relay.
- LG Home bypass creation and continued bypass during a short observation window;
  its stored expiry was verified as ten minutes. The full interval was not timed.
- Stock Home redirection and successful reconnection/redirection after terminating
  the watcher's Luna subscription; exactly one watcher remained.
- Live CPU, RAM, and temperature readings. Screenshots were captured from the TV webview.

Navigation events were injected through the TV debugger. Physical remote signal
delivery, HDMI picture/audio, reboot persistence, and other models/firmware were
not independently verified. The original TV preferences and usage state were restored.

## Updating

Use the archive and SHA-256 checksum attached to this release. Deploy both app and
service directories, including the new shared JavaScript modules. Existing
preferences and usage files should be preserved. Restart the launcher webview,
relay, and watcher so every process loads the new code.

This remains an update for an already rooted and registered installation; it does
not install root access, Luna permissions, or a persistent boot hook. See
[installation and recovery](https://github.com/Pragalbha-Patil/webos-minimal-home/blob/v1.4.0/docs/INSTALL.md).
